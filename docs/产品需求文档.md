# GitUnite — 产品需求文档

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 更新日期 | 2026-08-06 |
| 定位 | 本地运行的 GitHub / Gitee 个人编码数据看板 |
| 运行方式 | 纯前端 SPA，浏览器本地运行，无后端 |
| 数据存储 | IndexedDB（业务数据）+ LocalStorage（Token / 配置） |
| 开源协议 | MIT |

---

## 1. 产品概述

GitUnite 通过用户自行提供的 Personal Access Token（PAT），在浏览器内调用 GitHub / Gitee API，将名下及有权限访问的仓库、提交、PR/Issue 聚合到本地，并生成统计看板、时间轴、年度报告、成就徽章与分享卡片。

**原则**

- 隐私优先：Token 与业务数据不出浏览器，不上传第三方。
- 双平台：GitHub、Gitee 各绑定一个账号，看板支持单平台 / 聚合切换。
- 增量同步：再次打开优先拉取增量，并做限流与重试，降低配额消耗。

**非目标**

- 不做多用户 / 团队协作产品
- 不做源码内容分析、Webhook、实时推送
- 不依赖云端部署；移动端仅保证基础可浏览

## 2. 统一数据模型

平台差异在适配层抹平，内部统一为：

```text
Platform         = 'github' | 'gitee'
UnifiedUser      { id, login, name, avatarUrl, platform, htmlUrl }
UnifiedRepo      { id, platform, owner, name, fullName, description,
                   language, languages, stargazersCount, forksCount,
                   isPrivate, isFork, isOwned, isContributed, role, updatedAt, htmlUrl }
UnifiedCommit    { id, repoId, platform, sha, message, authorLogin,
                   authorName, authoredAt, additions, deletions, filesChanged, htmlUrl }
UnifiedIssue     { id, repoId, platform, number, type: 'pr'|'issue',
                   state, title, createdAt, closedAt, mergedAt, htmlUrl }
SyncCursor       { platform, repoId, lastCommitSha, lastSyncedAt, … }
```

仓库来源以 Token 权限下的 `/user/repos`（及等价接口）为主；GitHub 另可通过 Search 发现用户创建过的 PR/Issue（含外部仓，以合成 id 标记）。

## 3. 功能需求

### 3.1 账户接入

- PAT 手动录入；连接前调用 `/user` 校验。
- Token 存 LocalStorage；断开账号时清除该平台本地缓存。
- 账户卡片展示头像、昵称、最近同步、API 配额；区分 Token 无效 / 网络错误 / 限流 / 权限不足。
- 提示：不可信设备上勿使用（扩展可读取本机存储）。

**推荐权限**

- GitHub Fine-grained：Contents / Metadata 只读；需要 PR/Issue 时再开 Pull requests、Issues 只读。
- Gitee：`projects`、`user_info`；需要时再开 `pull_requests`、`issues`。

### 3.2 仓库列表

- Tab：全部 / GitHub / Gitee。
- 字段：名称、平台、描述、主语言、Star、Fork、更新时间、角色标签。
- 搜索、语言筛选、排序、仅看自己贡献过的仓库。

### 3.3 数据看板

视角：GitHub / Gitee / 聚合。时间按用户时区（可在设置覆盖）。

- **基础统计**：仓库数（Fork 单独计）、提交数（按 SHA 去重）、增删行、平均每次变更行数。
  - GitHub 代码量优先用贡献者周统计，并按已同步提交时间窗裁剪，避免与不完整历史错配。
  - Gitee 无周聚合时，依赖「代码明细」开关逐提交补齐；关闭则相关图表提示未开启。
- **活跃度**：首末提交日、活跃天数、日均提交、最长 / 当前 streak、小时与星期分布、深夜与周末占比。
- **语言分布**：环形图 / Top N；有字节量时按字节，否则按仓库主语言估算。
- **热力图**：提交频次（可选代码量），可切换年份。

### 3.4 提交时间轴

- 按日浏览提交；单日详情抽屉。
- message 搜索高亮；可过滤 merge 类提交。

### 3.5 协作关系图

- 以仓库为节点的力导向图（平台 / 聚合切换）。
- 「显示协作者」为可选增强：同步默认只拉当前用户 author 提交以省配额，因此多数情况下无协作者节点；界面需如实提示。

### 3.6 PR / Issue 贡献

- 创建数、合并数、Closed 未合并数（Issue 同理）；已合并 PR 的合并耗时中位数与平均值。
- 按 PR+Issue 数的仓库贡献 Top 10（含 GitHub 外部贡献仓）。
- Token 缺权限时展示引导，不打断其他同步。
- 同步仅由用户手动触发；完整同步才会拉取 PR/Issue。

### 3.7 年度报告与成就徽章

- 年份选择；年度提交、行数、活跃天数、streak、活跃月/周/时段、深夜与周末占比、语言与仓库摘要、commit message 词云。
- 本地成就徽章（夜猫子、早起鸟、全栈探索者等），结果可持久化「首次达成」时间。

### 3.8 数据导出与分享

- JSON：当前筛选范围内的仓库 / 提交 / Issue 与摘要统计。
- CSV：`commits.csv`、`repos.csv`（UTF-8 BOM，便于 Excel）。
- 分享卡 PNG（1200×630）：头像、昵称、提交数、语言数、活跃天、最长 streak、Top 3 语言、累计徽章；可隐藏身份；支持下载与复制到剪贴板。

### 3.9 设置与数据管理

- 时区、外观主题（浅色 / 深色 / 跟随系统）、界面语言（简体中文 / English）、代码明细开关。
- 导出 / 分享入口。
- 清除全部本地数据（Token + IndexedDB）。

### 3.10 同步策略（摘要）

- 首次全量；之后按游标增量；支持取消与跨标签页锁。
- 限流：读响应头、退避重试、平台并发与最小间隔。
- 仓库列表截断时不得误删本地已有仓库。
- Gitee 代码明细有单次同步请求上限，可多次同步继续补齐。

## 4. 技术栈

| 分类 | 选型 |
| --- | --- |
| 框架 | Vue 3 + TypeScript + Vite |
| 路由 / 状态 | Vue Router、Pinia、VueUse |
| 国际化 | vue-i18n（zh-CN / en-US） |
| UI | Naive UI、Tailwind CSS、lucide-vue-next |
| 图表 | ECharts、vue-echarts、echarts-wordcloud |
| 本地库 | Dexie（IndexedDB） |
| HTTP | axios（Token、限流、重试、ETag 会话缓存） |
| 时间 | dayjs（utc / timezone） |
| 导出 | Papa Parse（CSV + BOM）、html-to-image（分享 PNG） |
| 工程 | pnpm、ESLint、Prettier、vue-tsc、Vitest（可选） |

**目录（实际）**

```text
src/
  api/          # GitHub / Gitee 适配器与统一类型
  db/           # Dexie schema 与 repositories
  sync/         # 同步引擎、跨页锁
  stores/       # auth / sync / analytics / ui
  views/        # 看板、仓库、时间轴、协作、PR、年鉴、设置
  components/   # 图表、分享卡、设置面板等
  i18n/         # vue-i18n 语言包
  utils/        # 统计、徽章、导出、词云等
  workers/      # 重计算 Worker（年鉴等）
```

## 5. 已知限制

1. 协作图的协作者节点依赖本地是否有其他作者的提交；当前同步策略以「本人提交」为主。
2. GitHub Search 拉取 PR/Issue 受平台约 1000 条上限约束。
3. Gitee 外部仓 PR/Issue 仅覆盖本地已同步仓库列表，无跨仓 Search 等价能力。
4. 热力图年份选择器展示近年份；更早年份可在年鉴中查看。
5. 同步进度文案、部分图表内部标签仍可能以中文为主；单测覆盖可继续加强。
